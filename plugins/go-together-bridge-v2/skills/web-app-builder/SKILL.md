Inspect existing app state before changing it. Define screens, data contracts, actions, authentication and ownership. Use tools actually exposed in this conversation. Build working interactions, loading/error/empty states and responsive touch controls. Use GO Brain only for its existing knowledge purpose; do not replace it with app-local project memory or duplicate a Work database. Label synthetic demo data. Do not claim native Android/iOS build, PWA offline operation, backend connectivity or installed-app support without testing each. Verify core user actions and boundaries. For mobile fallback, prefer an existing authenticated GO Brain web UI using the same backend. Do not expose its private data through a public proxy or put owner credentials in HTML.

Read [shared rules](../../references/shared-rules.md) before acting. Check the current host's actual tools, connections and authorization; a skill cannot grant tool access. Distinguish instructions from implemented tools and runtime evidence.
